# 价策 AI：真实到手价与优惠工作流

## 1. 目标

系统要得到的不是页面上最醒目的数字，而是用户在明确条件下真正可以支付的价格。为避免“低价看得到、下单拿不到”，所有报价都保存价格组成、适用条件、账户口径、采集时间和可信度。

## 2. 唯一正式价格口径

正式报告只使用“账号结算预览价”：用户授权账号登录后，在指定数量、收货地区和优惠条件下，进入提交订单前页面看到的应付金额。公开页价格不再作为采集前置步骤，也不进入正式报告。

核算关系：`结算页商品金额 - 已验证可叠加优惠 + 运费 = 结算预览价`。优惠只有在购物车或结算页验证成功后才计入。系统不会提交订单或支付，因此不能把该结果称为“真实成交价”；如后续接入已支付订单回传，才可补充成交价字段。

## 3. 用户工作流

```text
导入 SKU / 商品链接
        ↓
选择平台账号；无有效账号则暂停
        ↓
首次在平台官方页面登录 → 本机保存独立会话并持续复用
        ↓
识别店铺券 / 平台券 / 品类券 / 会员折扣 / 满减 / 补贴 / 运费
        ↓
按“仅识别 / 逐次确认 / 规则授权”决定是否领取
        ↓
进入购物车核算 → 结算页二次复核 → 提交订单前停止
        ↓
保存账号结算预览价、账号画像、条件、时间与可信度
        ↓
进入价格诊断、拐点分析、调价模拟与报告
```

默认推荐“逐次确认”：用户只需首次登录，每次领取前看到优惠内容与限制；熟悉规则后可切换为规则授权。每个平台可以登记多个账号并随时切换，历史采集结果按账号隔离，不相互覆盖。验证码、实名、付费会员、支付或风险提示出现时，流程立即暂停并交还用户。

### 账号画像与报告说明

报告必须显示平台、账号别名、会员等级、收货地区、可用优惠范围、商品数量、采集时间和会话状态。跨平台矩阵允许每个平台选择不同账号，但必须在表头清楚说明；切换账号后生成新的报告版本，不能把不同账号价格混为无条件市场价格。

## 4. 商家优惠策略入口

商家可填写活动类型、门槛、优惠金额、有效期、适用 SKU、叠加规则和官方优惠链接。链接进入系统前必须通过：

1. HTTPS 与链接格式检查；
2. 平台域名白名单检查，防止仿冒域名；
3. 短链跳转后再次校验最终域名；
4. 活动 ID、门槛、有效期和适用范围解析；
5. 领取后再次核对购物车或结算前价格。

## 5. Python 服务

```bash
python -m collector_python.api
```

服务只监听 `127.0.0.1:8790`，提供：

- `POST /api/promotions/inspect`：校验并识别优惠链接；
- `POST /api/promotions/optimize`：计算可叠加的最优优惠组合；
- `POST /api/sessions/register`：登记本机浏览器授权状态文件；
- `POST /api/sessions/activate`：切换指定平台的当前采集账号；
- `GET /api/sessions`：查询平台授权状态；
- `GET /health`：健康检查。

Python 运行层零第三方依赖。浏览器登录状态由用户在平台官方页面产生，系统只登记本机状态文件路径，不接收密码，也不把授权数据提交到 GitHub。`checkout_adapter.py` 会校验结算结果与账号平台一致，并输出统一的 `checkout_preview` 价格口径。

## 6. Agent 维护闭环

页面结构变化时，系统先由采集成功率、字段缺失率和价格波动异常触发漂移告警，再将脱敏后的失败页面快照交给本地代码模型生成“修复建议”。建议只能涉及解析器与测试：

```text
漂移告警 → 快照脱敏 → Agent 修复建议 → 沙箱单测
       → 人工审核 → 小流量灰度 → 指标正常后放量 / 异常回滚
```

Agent 不读取 Cookie、Token 或密码，不处理验证码，不直接部署代码。`collector_python/agent_guard.py` 对建议文件范围和审核状态实施硬约束；可在本机接入 Ollama 等免费本地模型，但模型只是提议者，不是生产发布者。

## 7. 价格准确性护栏

- 未选择有效登录账号时不采集价格。
- 不从模糊文本猜价格，只接受购物车/结算页明确金额或正式授权接口。
- 同一 SKU、数量、地区、时刻和会员条件才直接比较。
- 结算前二次验证；验证失败则降级为“估算价”，不能标为实际价。
- 异常低价、优惠过期、库存不足和价格突变进入人工复核。
- 原始快照、解析版本、优惠组合与计算结果可追溯。

## 8. 当前交付边界

仓库已实现多账号会话登记与切换、账号画像、结算预览结果规范化、优惠组合核算、官方域名识别、受控 Agent 修复提案、前端交互演示和自动化测试。真实平台的浏览器登录、自动领取与结算页操作仍需逐平台配置浏览器适配器；当前界面中的账号与结算结果为可测试的产品演示数据，不应误称已经打通平台生产账号。
