# 价策 AI：真实到手价与优惠工作流

## 1. 目标

系统要得到的不是页面上最醒目的数字，而是用户在明确条件下真正可以支付的价格。为避免“低价看得到、下单拿不到”，所有报价都保存价格组成、适用条件、账户口径、采集时间和可信度。

## 2. 四层价格口径

| 口径 | 定义 | 是否进入公开市场中位数 |
|---|---|---|
| 划线价 | 页面展示的参考原价 | 否 |
| 公开售价 | 无需登录或领券即可复现 | 是 |
| 条件可实现价 | 满足门槛并领取可用优惠后的估算 | 仅在同条件样本中比较 |
| 已持券实际价 | 当前授权账户已持有优惠后的可验证价格 | 否，单独展示 |

最终价计算：`公开售价 × 数量 - 可叠加优惠 + 运费`。系统枚举可用优惠组合，遵守互斥组、满减门槛和领取状态，选择最低合法组合；会员价、新客价、地区补贴和账户定向券会标记为个性化价格。

## 3. 用户工作流

```text
导入 SKU / 商品链接
        ↓
采集公开售价与公开活动
        ↓
需要账户优惠？── 否 ──→ 输出公开可复现价
        │ 是
        ↓
首次在平台官方页面登录 → 本机复用授权状态
        ↓
识别店铺券 / 平台券 / 品类券 / 会员折扣 / 满减 / 补贴 / 运费
        ↓
按“仅识别 / 逐次确认 / 规则授权”决定是否领取
        ↓
核算可实现到手价 → 保存条件、来源、时间、可信度
        ↓
进入价格诊断、拐点分析、调价模拟与报告
```

默认推荐“逐次确认”：用户只需首次登录，每次领取前看到优惠内容与限制；熟悉规则后可切换为规则授权。验证码、实名、付费会员、支付或风险提示出现时，流程立即暂停并交还用户。

## 4. 商家优惠策略入口

商家可填写活动类型、门槛、优惠金额、有效期、适用 SKU、叠加规则和官方优惠链接。链接进入系统前必须通过：

1. HTTPS 与链接格式检查；
2. 平台域名白名单检查，防止仿冒域名；
3. 短链跳转后再次校验最终域名；
4. 活动 ID、门槛、有效期和适用范围解析；
5. 领取后再次核对购物车或结算前价格。

## 5. Python 服务

```bash
python -m collector_python.api
```

服务只监听 `127.0.0.1:8790`，提供：

- `POST /api/promotions/inspect`：校验并识别优惠链接；
- `POST /api/promotions/optimize`：计算可叠加的最优优惠组合；
- `POST /api/sessions/register`：登记本机浏览器授权状态文件；
- `GET /api/sessions`：查询平台授权状态；
- `GET /health`：健康检查。

Python 运行层零第三方依赖。浏览器登录状态由用户在平台官方页面产生，系统只登记本机状态文件路径，不接收密码，也不把授权数据提交到 GitHub。

## 6. Agent 维护闭环

页面结构变化时，系统先由采集成功率、字段缺失率和价格波动异常触发漂移告警，再将脱敏后的失败页面快照交给本地代码模型生成“修复建议”。建议只能涉及解析器与测试：

```text
漂移告警 → 快照脱敏 → Agent 修复建议 → 沙箱单测
       → 人工审核 → 小流量灰度 → 指标正常后放量 / 异常回滚
```

Agent 不读取 Cookie、Token 或密码，不处理验证码，不直接部署代码。`collector_python/agent_guard.py` 对建议文件范围和审核状态实施硬约束；可在本机接入 Ollama 等免费本地模型，但模型只是提议者，不是生产发布者。

## 7. 价格准确性护栏

- 不从模糊文本猜价格；优先开放 API、JSON-LD 和明确价格字段。
- 同一 SKU、数量、地区、时刻和会员条件才直接比较。
- 结算前二次验证；验证失败则降级为“估算价”，不能标为实际价。
- 异常低价、优惠过期、库存不足和价格突变进入人工复核。
- 原始快照、解析版本、优惠组合与计算结果可追溯。

## 8. 当前交付边界

仓库已实现优惠组合核算、官方域名识别、本机会话登记、受控 Agent 修复提案、Python API、前端演示和自动化测试。真实平台的自动领取与结算校验仍需商家主体申请对应平台 API 权限，并在用户明确授权下配置浏览器自动化；产品不会绕过平台控制。
